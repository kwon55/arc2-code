## 단계별 계획

### Phase 1 — 루프 1바퀴 완주 (최우선)

목표: **"서술 LoRA 가 점수를 올리는가"에 대한 첫 측정된 답.** ACCEPT 든 REJECT 든 숫자와 함께.

1. 셀3 r0 채굴 계속 — `teacher_done_r0.json` 커서로 재개, 목표 태스크 수까지
2. 셀4 본실행 (지금은 스모크 4태스크뿐 — 코드 원천 ①②③ 전체로)
3. 셀5 — `human_training_memo.txt` 있으면 실행, 없으면 건너뛰고 여기 비고
4. 셀6 조립 → 행 수·출처 분포·가중 분포 기록
5. 셀7 `A.smoke=True` 파일럿 (r64 메모리 피크 확인) → 본학습
6. 셀8 — 적용 증명이 **G6 를 판정**한다. 실패 시 `final_vllm` → 병합→FP8 경로.
   사다리 L1~L5 → 연구 판정 / 채택 판정 분리 기록

출구 조건: `ladder_*.json` + 이 문서 결정 로그에 판정 한 줄.

### Phase 2 — 판정에 따라 분기

- **ACCEPT** → R1 재채굴 (LoRA 보조 교사) 1~2 라운드. 2 라운드 연속 UNDECIDED(짝지은 승패 ±3 미만)면 이 축 동결
- **REJECT** → L1~L4 중 어디서 깨졌는지 원인 한 줄 기록 후 ② 축으로 전환

### Phase 3 — ② NVARC 합성 데이터

1. `sft139/config.json` 확인 — 모델 정체 (크기·구조)
2. `syn_training` 716 을 셀3 few-shot / 조립 보강으로 — 셀6 출처 검사가 eval tid 를 거른다 (구현돼 있음)
3. `syn_full` 은 제출용 학습만. 공개 eval 사다리에서는 syn_full 을 본 모델끼리만 비교

### Phase 4 — ④ 제출 + 리허설 (Phase 1 판정과 무관하게 마감 전 확보)

- 제출 노트북에 셀2 그대로 + 서술 호출만 LoRA (`LoRARequest('desc',1,path)`), 코드·수리 호출은 베이스
- 동일 시간 예산 리허설 — 처리량이 채택 기준의 일부다 (셀0 판정 규칙)
