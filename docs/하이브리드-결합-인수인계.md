## 2. 확정 전략

**본대(kgmon) + Qwen3.8-27B 보조.** (Qwen2.5-Instruct 대체는 하지 않는다.)

- 보조는 **맨 마지막** 고정 슬라이스(1.5~2.0h 하드캡)에서만 돈다.
- 보조의 대상은 본대 결과에서 **빈 유닛 + 후보 빈약 태스크**만.
- 보조 후보는 **train 전쌍 재현 검증** 통과분만 채택 (v60의 "전쌍통과 제출" 로직 그대로).
- 병합은 v2.4.2 정책 그대로: **attempt_1 불가침, 빈 유닛 → attempt_2 순**.
- 단, 결합 작업 착수 전에 **§3 게이트를 먼저 통과**해야 한다. 게이트는 GPU 오프라인 런 2회, 제출 0회.

**GO/NO-GO 게이트 (v2, 1005 갱신 — 2단계)**: 공개 eval 120 오프라인 기준.
- **1단계 (공짜, 기존 전예산 런으로)**: `보조가 맞히고 본대는 놓친 태스크(고유 해결) ≥ 4개`.
  고유 해결은 순증의 **상한**이므로, 미달이면 그 자리에서 STOP — 더 잴 것 없음.
- **2단계 (오프라인 1회 측정)**: 본대 예산을 보조 몫만큼 깎을 때의 손실을 빼야 한다.
  본대가 **마지막 1.5~2h에 푸는 태스크 수(꼬리 손실)** 를 eval-dump 시간 로그에서 세고,
  `순증 = 고유 해결 − 꼬리 손실 − 병합 손실 ≥ 4태스크(≈+3.3점)` 일 때만 결합 제출.
  (근거: 태스크 1개 ≈ 0.83점. LB 노이즈 ±2.5 위로 올라오려면 순증 +3점 이상 필요.
  고유 4개를 얻어도 본대 꼬리에서 5개를 잃으면 손해다.)

## 3. 실행 절차 (체크리스트)

### Step 1 — 재료 2개 만들기 (제출 아님, Save & Run 또는 Colab)

**(a) 본대 eval 채점본** — `44-v3` 노트북을 제출하지 말고 그냥 실행.
`KAGGLE_IS_COMPETITION_RERUN` 이 없으면 자동으로 eval 모드가 되어
`arc-agi_evaluation_challenges.json` 을 풀고 마지막에 `*** Reload score:` 를 출력한다.
산출물 `submission.json` 을 **`kgmon_eval_submission.json`** 으로 저장/다운로드.
(이미 갖고 있는 `4H eval-dump` 계열 산출물이 있으면 그걸 재사용해도 된다.)

**(b) 보조 eval 채점본** — `v60` 노트북의 오프라인 리허설 풀을
`train 4 + eval 1` → **eval 120 전체**로 바꿔 실행 (셀2의 대상 풀 설정).
산출물 `submission.json` 을 **`v60_eval_submission.json`** 으로 저장.
- 12h 안에 120개를 다 못 돌면 완료분만으로 계산한다 — 고유 해결 수가
  **과소평가**될 뿐이므로 게이트 판정에는 안전한 방향이다.

### Step 2 — 고유 해결 계산 (아래 §4 코드, CPU 몇 초)

세 파일을 한 폴더에 두고 실행:
`arc-agi_evaluation_solutions.json` / `kgmon_eval_submission.json` / `v60_eval_submission.json`

### Step 3 — 판정 (2단계 게이트)

- 1단계: `보조 고유 해결 < 4` → **STOP**. 이 축을 동결하고 결정 로그에 한 줄 기록. (제출 안 함 = 손해 0.)
- 1단계 통과 시 2단계: 본대 eval 런의 시간 로그에서 **마지막 1.5~2h에 풀린 태스크 수**(= 꼬리 손실)를 센다.
  `고유 해결 − 꼬리 손실 ≥ 4` → **GO**, §5 결합 명세로. 미만 → STOP 또는 보조 몫 축소 후 재계산.
- 참고: v60 쪽 효율 개선(비동기·캐시·상태 복원 등)은 별도 문서의 파일럿 절차를 따르되,
  **최소 계측(요청별 타임스탬프, cached/total prompt tokens)을 먼저 추가**하고 측정된 병목 하나만 바꾼다.
  기존 LEDGER에는 요청별 시각이 없어 락스텝 대기 시간을 복원할 수 없다 (1005 확인).

### Step 4 — (GO 시) 결합 노트북 수정 (§5 명세)

### Step 5 — 오프라인 리허설 1회
eval 소수 태스크 + 시간 로그로: 본대 정상 종료 → vLLM 기동 성공 → 보조 하드캡 준수 →
병합 셀 ✅ → 오프라인 점수 ≥ 본대 단독. 전부 확인 후에만 제출.

### Step 6 — 제출은 그 구성 **한 판**. 결과(점수·고유해결 실측)를 결정 로그에 기록.

## 4. 고유 해결 계산 코드 (새 창에서 그대로 실행)

```python
# ============================================================
# [고유해결 게이트] 본대 vs 보조 — 공개 eval 오프라인, GPU 0초, 제출 0회
# 필요 파일 (같은 폴더):
#   arc-agi_evaluation_solutions.json   (대회 Data 탭)
#   kgmon_eval_submission.json          (Step 1a 산출물)
#   v60_eval_submission.json            (Step 1b 산출물)
# 판정: unique(v60만 정답) >= GATE 이면 GO
# ============================================================
import json

GATE = 4  # 태스크 1개 = 100/120 = 0.83점. 4개 = +3.3점 (LB 노이즈 ±2.5 초과 기준)

sol   = json.load(open("arc-agi_evaluation_solutions.json"))
kgmon = json.load(open("kgmon_eval_submission.json"))
v60   = json.load(open("v60_eval_submission.json"))

def unit_ok(sub, tid, k, gt):
    """유닛 k 가 attempt_1 또는 attempt_2 로 정답인가."""
    units = sub.get(tid)
    if not units or k >= len(units):
        return False
    u = units[k] or {}
    return u.get("attempt_1") == gt or u.get("attempt_2") == gt

def task_score(sub, tid):
    """대회 방식: 태스크 점수 = 맞힌 유닛 비율 (0.0~1.0)."""
    gts = sol[tid]
    return sum(unit_ok(sub, tid, k, gt) for k, gt in enumerate(gts)) / len(gts)

rows = []
for tid in sorted(sol):
    a, b = task_score(kgmon, tid), task_score(v60, tid)
    rows.append((tid, a, b))

solved_kg  = {t for t, a, b in rows if a == 1.0}
solved_v60 = {t for t, a, b in rows if b == 1.0}
uniq_v60   = solved_v60 - solved_kg          # 보조만 완전 정답
uniq_kg    = solved_kg - solved_v60
partial    = [(t, a, b) for t, a, b in rows if b > a]  # 유닛 단위로라도 보조가 우세

n = len(sol)
print(f"태스크 {n} | 본대 완전정답 {len(solved_kg)} ({100*len(solved_kg)/n:.2f}점) "
      f"| 보조 완전정답 {len(solved_v60)} ({100*len(solved_v60)/n:.2f}점)")
print(f"겹침 {len(solved_kg & solved_v60)} | 본대만 {len(uniq_kg)} | ★보조만 {len(uniq_v60)}")
print(f"보조 고유 태스크: {sorted(uniq_v60)}")

# 병합 시 기대 상승 상한 (attempt_2 자리를 쓸 수 있다는 낙관 가정)
gain_units = sum(b - a for _, a, b in rows if b > a)
print(f"유닛 단위 이득 상한: +{100*gain_units/n:.2f}점 "
      f"(보조 우세 태스크 {len(partial)}개 상세: {[(t, round(a,2), round(b,2)) for t,a,b in partial]})")

print("=" * 60)
if len(uniq_v60) >= GATE:
    print(f"판정: GO — 고유 {len(uniq_v60)} >= {GATE}. §5 결합 명세로 진행.")
else:
    print(f"판정: STOP — 고유 {len(uniq_v60)} < {GATE}. 이 축 동결, 결정 로그에 기록.")
```

주의: 두 submission 이 **같은 태스크 집합(eval 120)** 을 대상으로 만들어졌는지 확인.
v60 이 일부만 완료했다면 그 사실을 출력에 함께 기록해 둘 것 (고유 수는 과소평가 방향).

## 5. (GO 시) 결합 노트북 수정 명세

베이스: `submit-33-1-mymodel-kgmon-arc26-2025-win.ipynb` (결합 v2.4.2). 변경 4가지.

### 5-1. 시간표 — 보조는 맨 뒤, 하드캡
```
스위프(기존 몫 유지 또는 축소) → 본대 kgmon ≈ 8.5~9h → 보조 1.5~2.0h → 병합 셀
```
- 구현: 셀2의 `global_end_time = time.time() + 12*3600 - 600` 을
  **본대용 데드라인**으로 당긴다 (예: `- 600 - AUX_BUDGET`, `AUX_BUDGET = 2*3600`).
  보조 페이즈는 자기 데드라인(`global_end_time + AUX_BUDGET`)을 스스로 지킨다.
- vLLM 기동(10~15분)은 보조 몫에 포함시킨다.
- **본대에서 2h 넘게 깎지 않는다.** (12h→10h 손실분은 리허설에서 태스크 완료 수로 확인.)

### 5-2. 보조 대상 선정 — 본대 결과를 보고 고른다
본대 `submission.json` 에서:
1. **빈 유닛**(`[[0]]`) — 최우선.
2. `attempt_1 == attempt_2` 인 태스크 — 후보 부족 신호.
3. (여유 시) 셀 수 적은 순.
이 목록만 v60 에이전트 루프의 대상 풀로 넘긴다. **본대가 이미 두 attempt 를 채운
멀쩡한 태스크는 건드리지 않는다.**

### 5-3. 보조 채택 필터 — v60 로직 재사용
- **train 전쌍통과** 후보만 정식 채택 (v60 명부의 `submitted & not forced` 에 해당).
- `forced`(강제) 후보는 **빈 유닛 채움에만** 허용.

### 5-4. 병합 — v2.4.2 불변 정책에 공급원 하나 추가
- attempt_1 불가침. 보조 후보는 **빈 유닛 → attempt_2** 순서로만.
- attempt_2 배분 우선순위에 보조(전쌍통과)를 스위프 후보들과 나란히 넣되,
  전쌍통과 검증이 있는 후보를 위로.
- 원자 저장(tmp → os.replace), `FORCE_FIX_F`/`KGMON_F_REPAIR` 등 기존 플래그 유지.

### 5-5. VRAM 절차
본대 프로세스 **완전 종료** (subprocess 분리 / `torch.cuda.empty_cache()` + gc) 후에
vLLM 기동. v60 셀7(엔진 기동)·셀1(휠하우스 오프라인 설치) 코드를 그대로 가져온다.
