v3 인수인계 최종 검토

핵심 판정 방식에 동의합니다. 같은 총예산에서 실제 병합 제출 H와 본대 단독 F를 비교하고, 추가 정답과 잃은 정답을 따로 집계하면 됩니다. 이전의 꼬리 복구 누락 문제도 해결됐습니다.

실행 전에 두 문구만 수정하십시오.

1. “본대가 놓친 태스크를 겨냥”은 제출 시 관측 가능한 신호로만 구현해야 합니다.
공개 eval 정답으로 본대 오답 태스크를 골라 보조를 실행하면 oracle 선택이 되어 제출에서 재현할 수 없습니다. 보조 대상은 빈 출력, 중복 후보, 후보 개수, 모델 점수 등 정답 없이 얻는 정보로 정하고, 기준을 미리 고정하십시오. 정답은 사후 겹침 계산과 최종 채점에만 사용합니다. 문서의 “빈 유닛 + 후보 빈약 태스크” 방향은 맞으며, “후보 빈약”의 정의가 코드로 명시되어야 합니다.

2. “3 게이트, GPU 런 2회”는 현재의 2단계 게이트와 맞지 않습니다.
기존 결과가 없다면 본대 전예산 F와 보조 전예산 결과를 얻는 두 런이 필요합니다. 이 두 런은 보완성 선별 재료이고, 실제 결합 H의 실행을 대신하지 않습니다. 이후 결합 리허설이 추가로 필요합니다. 기존 결과와 체크포인트를 재사용할 수 있는 경우 비용을 줄일 수 있지만, 총 두 런으로 고정하지 마십시오.
권장 문구: “2단계 게이트. 기존 결과가 없으면 기준선 두 런을 확보하고, 선별 통과 후 실제 결합 리허설을 추가한다. 필요한 런 수는 재사용 가능한 산출물에 따라 달라진다.”

덧붙여 F와 H는 제출 파일이고, |H|-|F|에서 세는 것은 파일의 태스크 키 수가 아니라 정답 수입니다. 코드에서는 score(H)-score(F), 또는 정의된 정답 집합 S_H와 S_F에 대해 |S_H|-|S_F|로 쓰십시오. 실제 평가 함수의 다중 test 입력 집계 방식도 동일하게 적용해야 합니다.

이 두 조건을 반영하면 더 이상 전략 문구를 반복 수정할 필요는 없습니다. 다음은 예측 파일, 설정·시드·데이터 목록, 시간별 후보/제출 스냅샷을 확보하는 단계입니다. 붙여주신 내용은 2단계 설명 도중에서 끝났으며, 원격 커밋이나 생략된 문서 후반은 이번에 확인하지 않았습니다.
